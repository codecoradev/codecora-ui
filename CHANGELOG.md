# Changelog

All notable changes to this repository are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Packages are
versioned independently with [Semantic Versioning](https://semver.org/)
(0.x: minor = features, patch = fixes); per-package changelogs are generated by
changesets once packages exist.

## [Unreleased]

### Added

- Planning documents: decisions D1–D12, architecture, roadmap M0–M4 with the issue map.
- Repository baseline: `AGENTS.md`, contributing guide, code of conduct, security policy, PR template and issue forms, commit hooks (`scripts/hooks/`), PR checks and review workflows.
- Dependabot for GitHub Actions.
- Monorepo tooling: bun workspaces, strict TypeScript 6, `svelte-package` + publint, vitest with Testing Library, ESLint and Prettier, changesets; `@codecora/ui` and playground skeletons.
- `@codecora/tokens`: primitive, semantic and theme tiers with the `neutral`, `uteke` and `corin` themes, `data-accent` and `data-density` modifiers, nesting per element, a Tailwind 4 preset and a shadcn-svelte bridge; WCAG AA contrast check for every theme and accent.
- Design context for the impeccable workflow: `PRODUCT.md`, a shared `DESIGN.md`, one `docs/design/<theme>.md` per theme kept in sync with the tokens by a test, and `bun run detect`.
- Playground catalogue: theme, accent and density switchers, colour roles, control states, type, radius and spacing scales, a nested-theme demo, the contrast table per theme and accent, and fixed `/themes/<name>` pages for visual snapshots.
- CI: a `Gates` workflow (lint, check, test, build, contrast, detector, pack dry run) on every PR and push to `develop` and `main`, and a `Release` workflow that publishes to npm with trusted publishing and provenance from `main`, dry run until publishing is enabled.
- `@codecora/ui`: first primitive set on bits-ui (Button, IconButton, Field, Input, Textarea, Select, Dialog, ConfirmDialog, Sheet, Tabs, Table, Badge, Toast, Tooltip, EmptyState, Skeleton, Spinner) with unit tests; a Components page in the playground and screenshots under `docs/assets/screenshots/`.
- Playground: an admin dashboard sample at `/dashboard` built from the primitives (sidebar and navigation sheet, usage summary, chart, filterable keys table, revoke flow), a shared appearance store for its pages, and its screenshots.
- `@codecora/ui`: `AppShell` and `Sidebar` (grouped navigation with brand and footer slots, collapsible on desktop, a drawer and a bottom bar of up to 5 items on narrow screens, a skip link, a per-region sidebar theme) with unit tests; the dashboard sample now uses them.
- `@codecora/ui`: error states and ConfirmDialog hardened after the impeccable critique of the primitives (see Fixed).
- `@codecora/icons`: an `Icon` wrapper that follows the theme's icon size and stroke, a curated Lucide set (`@codecora/icons/lucide`) and a Phosphor adapter (`@codecora/icons/phosphor`); an Icons page in the playground. The playground demos now take their icons from the package.

### Fixed

- `Table`: the visually hidden caption and header labels no longer widen the page on narrow screens.
- `Field` errors no longer rely on colour alone (icon and "Error:" prefix), `required` reaches the control, and invalid controls have a stronger border; `ConfirmDialog` forwards `theme`, focuses Cancel first for danger, emphasises the irreversible sentence and can require a typed name; `Button` accepts a `loadingLabel`.

### Security

- Workflows: the review access token is a step output instead of a job-wide variable, actions are pinned to commit SHAs, the message standard runs from the base branch, and the PR description check requires real content under whole `## What` / `## Why` / `## Testing` headings.
